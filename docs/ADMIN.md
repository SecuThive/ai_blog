# 관리자 페이지

`/admin` → 로그인 후 블로그 글·엔지니어 가이드·댓글·문의·구독자 관리. 모바일 브라우저에서도 동일하게 사용할 수 있습니다.

## 최초 설정

자체 PostgreSQL/PostgREST 환경을 사용하며 Supabase Auth는 필요하지 않습니다.

1. 프로젝트 루트에서 `node scripts/setup-admin.mjs admin` 실행.
2. 생성된 `.secrets/admin-login.txt`에서 임의 생성된 비밀번호를 확인하고 비밀번호 관리자에 저장합니다. 이 파일은 git에서 제외되며 소유자에게만 읽기 권한이 있습니다. 보관 후 삭제하세요.
3. 서버를 재시작합니다. `/admin/login`에서 로그인합니다.

스크립트는 `.env.local`에 서버 전용 `ADMIN_USERS_JSON`, `ADMIN_SESSION_SECRET`를 추가합니다. 기존 설정이 있으면 덮어쓰지 않습니다. 운영 배포에는 같은 환경변수를 안전하게 전달하고 HTTPS 및 정확한 `NEXT_PUBLIC_SITE_URL`을 설정하세요. 로컬 환경의 계정 생성은 운영 배포를 의미하지 않습니다.

추가 관리자는 `ADMIN_USERS_JSON` 배열에 `{email,passwordHash}`를 추가합니다. 기존 호환 필드인 `email`에는 아이디 또는 이메일을 입력합니다. 해시는 `scrypt:<16바이트 salt의 hex>:<64바이트 key의 hex>` 형식입니다. 평문 비밀번호를 환경변수에 넣지 마세요. 모든 등록 관리자는 같은 관리 권한을 가집니다. 초기 설정과 계정 발급·비밀번호 변경은 서버 운영자가 담당하며, UI에서는 콘텐츠·댓글·문의·구독자를 관리합니다.

## 사용

- 글/가이드: 제목 검색, 상태 필터, 페이지 이동, 신규 작성, Markdown 미리보기, 메타데이터 수정, 발행·비공개 전환, 영구 삭제.
- 발행 저장 시 내용 검토 확인이 필요합니다. 블로그와 가이드에 서버가 실제 로그인 계정의 검토 기록을 기록합니다.
- 발행된 글의 URL 변경은 기존 링크를 끊을 수 있습니다. 기존 주소를 유지하는 것을 권장합니다.
- 댓글: 공개·숨김 전환 및 삭제. 문의와 구독자: 검색·상세 조회·삭제. 메일 자동 발송은 하지 않습니다.
- 삭제는 복구 불가능하므로 확인 창을 표시합니다. 글 공개만 중단할 때는 비공개로 저장하세요.
- 글 편집 중 다른 관리자에 의한 변경은 `updated_at` 조건부 업데이트로 충돌을 감지합니다.

## 보안 및 운영

- 비밀번호는 Node.js scrypt로 해시하고 timingSafeEqual로 비교합니다. 세션은 HMAC-SHA256으로 서명하며 최대 1시간 유효합니다.
- 쿠키: HttpOnly, SameSite=Strict, 운영에서 Secure. 인증은 페이지와 모든 관리 API에서 확인합니다. 변경 요청은 Origin을 검증합니다.
- 계정을 제거하거나 비밀번호 해시를 변경하면 기존 세션은 즉시 무효화됩니다(모든 서버에 새 설정 적용 필요). 서명 키 교체는 모든 세션을 무효화합니다.
- 로그아웃은 해당 브라우저 쿠키를 삭제합니다. 탈취된 쿠키까지 즉시 취소하려면 비밀번호 또는 서명 키를 교체하세요.
- 로그인 제한은 프로세스별 계정당 15분 5회·전체 분당 50회입니다. 다중 서버나 프로세스 재시작을 가로지르는 제한에는 프록시/Cloudflare에서 `/api/admin/session` POST에 추가 제한을 설정해야 합니다.
- DB의 `reviewed_at`, `reviewed_by` 컬럼과 기존 발행 검토 트리거를 사용합니다. 가이드는 `docs/adsense-audit/sql/2026-10-03-phase2-triggers.sql`의 기존 마이그레이션이 필요합니다.
- 원격 DB에 연결되지 않으면 관리 화면은 오류를 표시하고 저장 성공으로 처리하지 않습니다.
- 공개 `/api/posts/[id]`는 발행된 글만 반환합니다. 관리 화면은 별도의 인증된 API로 초안을 읽습니다.

## 검증

`npm test`, `npm run typecheck`, 변경 파일 ESLint. 로그인·원본 검증·쿠키·권한 및 실제 작성 흐름은 격리된 테스트 데이터로 확인합니다. 운영 DB 데이터는 검증 목적으로 변경하지 않습니다.

## 현재 화면 구성

관리 화면의 스타일은 `src/app/admin/admin.css`에 있습니다. 기존 `src/app/globals.css`의 어두운 배경·표면색과 밝은 본문색을 이어받는 별도 스타일시트이며, 주요 작업은 파란 버튼, 삭제는 붉은 글자, 공개 상태는 녹색 표시와 텍스트로 구분합니다. 한국어 레이블과 Pretendard 우선 글꼴을 사용합니다.

데스크톱은 왼쪽 메뉴와 목록 표, 본문·설정 두 열의 편집 화면으로 구성됩니다. 편집 화면은 1100px 이하에서 한 열로, 메뉴는 720px 이하에서 상단 가로 메뉴로 바뀝니다. 모바일 표는 가로로 스크롤하며 상세 정보와 입력 폼은 세로로 배치됩니다. 키보드 포커스에는 파란 윤곽선을 표시합니다. 이는 현재 코드의 구현 기록이며 별도 사용자 디자인 선호를 정의하지 않습니다.
