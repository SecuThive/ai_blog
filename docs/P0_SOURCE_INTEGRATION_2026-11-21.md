# P0 운영 수정의 원본 통합

2026-11-21. 비교 기준: 현재 운영 `.deploy/20261121-seo-p0/schema` (기존 P0 + 구조화 데이터 수정). 원본의 기존 변경 위에 필요한 수정만 통합했다. 운영 교체·커밋·푸시는 하지 않았다.

## 통합한 수정

- 블로그·엔지니어 글: 실제 영문 본문이 없으면 영문 URL을 한국어 원문으로 307 이동. 제목만 번역된 경우도 본문 번역으로 취급하지 않는다.
- metadata: 번역 없는 URL의 en hreflang 제외 및 한국어 canonical. 한글/공백/이미 인코딩된 URL을 한 번만 정규화하여 JSON-LD·canonical·사이트맵 URL을 일치시킨다.
- 사이트맵: 번역 여부에 맞춰 영문 URL과 상호 hreflang을 생성한다. 본문은 조회 후 판정하고 캐시에는 hasEnglish만 저장하여 Next 데이터 캐시의 용량 문제를 방지한다. 기존 10초 조회 제한 유지.
- 시리즈: 조회 오류를 빈 목록/404로 오인하지 않도록 예외 처리. 구조화 데이터는 번역이 실제 존재하는 언어 URL을 가리킨다.
- 엔지니어 목록: 구조화 데이터의 목록 URL에 현재 언어를 반영한다.
- 추가 발견: DB 장애 시 정적 축소 사이트맵에도 영문 loc를 포함시켜 대체 링크 상호 참조를 유지한다.
- 기존 구조화 데이터 수정(editor, ItemList, JSON-LD 이스케이프)은 그대로 유지한다.

## 가져오지 않은 운영 릴리스의 오래된 차이

원본에 있던 다음 작업을 보존했다. 운영 릴리스의 전체 파일로 덮어쓰지 않았다.

- 기존 잘못된 한글 slug의 HTTP 301 처리, POST_REDIRECTS 추가 항목.
- 잘못된 URI의 앱 수준 예외 처리.
- 현재 원본의 기본 robots, max-video-preview, 태그 색인 정책.
- 과거 품질 점수 목록을 홈 추천·광고 범위에만 적용하는 정책. 운영 릴리스의 NOINDEX_POST_SLUGS 기반 일괄 색인 제외를 재도입하지 않았다.
- 발행 글 1개 이상인 시리즈 색인 정책. 사이트맵 기준도 1개 이상으로 일치시켰다.
- UI·관리자·광고·콘텐츠 작업과 PM2 설정.

따라서 후보 사이트맵은 기존 운영의 1,064개와 동일한 숫자를 강제하지 않는다. 실제 후보 1,173개는 원본의 기존 색인 정책을 유지한 결과이며, 대체 URL 포함 여부·상호성·샘플 페이지 robots를 검사했다.

## 테스트 및 검증

- 기존 테스트 27개, JSON-LD 렌더링 2개, 번역 본문 유무 9개 통과.
- 실제 sitemap/metadata 코드를 실행하는 계약 검사 통과: URL 정규화, 번역별 포함/제외, 양방향 hreflang, 본문 캐시 제거, 기존 redirect 제외, 단일 글 시리즈 정책, DB 장애 폴백. DB와 Next 캐시만 모의 처리하며 DB는 수정하지 않는다.
- 독립 복사본에서 `npm run build` 통과: prebuild 테스트, 컴파일, TypeScript 및 정적 생성 성공.
- 독립 후보 서버 localhost:3114에서 사이트맵 1,173개 상호 참조 검사 통과. 카테고리·시리즈·엔지니어 목록·대표 글 55개 HTTP/canonical/hreflang/JSON-LD/robots 검사 실패 0. 모든 1,173개 본문을 요청한 것은 아니다.
- 번역 없는 대표 영문 URL 3개 모두 HTTP 307, 한국어 원문으로 이동, 사이트맵에서 제외.
- 기존 한글 slug 리다이렉트 2개 HTTP 301 유지.
- 별도 탐색한 잘못된 퍼센트 인코딩 `/blog/%E0%A4%A`는 후보와 기존 운영 모두 HTTP 500이다. 이번 통합으로 새로 발생한 회귀는 아니며, 프레임워크 수준 비정상 URL 처리는 이번 범위 밖의 잔여 항목으로 남긴다.
- `git diff --check` 통과. 변경 전 해시와 비교하여 지정한 기존 파일 외 사용자 작업 보존 확인.

## 다음 배포에서 실행

1. 검토된 원본 소스로 새 릴리스를 준비한다. 작업 트리 변경은 아직 커밋·푸시되지 않았으므로 Git 기반 배포 전 변경을 포함해야 한다.
2. `npm run build` — prebuild가 기존 테스트, schema 검사, P0·사이트맵 계약 검사를 실행한다. 직접 next build 또는 ignore-scripts로 우회하지 않는다.
3. 새 릴리스를 비어 있는 로컬 포트에서 시작한다. 예: `npm start -- -H 127.0.0.1 -p 3114`.
4. `npm run test:seo:live -- http://127.0.0.1:3114` — 실제 DB의 대표 콘텐츠를 포함한 배포 후보 검증. 정적 축소 사이트맵만 반환되면 대표 글 부재로 실패하도록 되어 있다.
5. 통과 후 해당 릴리스의 ecosystem 설정으로 thivelab-web만 교체하고 운영 URL을 확인한다. 현재 운영 경로는 `.deploy/20261121-seo-p0/schema`, 운영 포트는 3103이다. PM2 전체 apps를 재시작하지 않는다.

검증 중 생성한 임시 빌드·서버는 종료·정리하고 기존 운영 릴리스와 DB·백업은 보존했다.
