# 구조화 데이터 수정 통합 및 다음 배포

2026-11-21 원본 작업 트리에 구조화 데이터 패치 통합 완료.

## 포함된 변경

- 블로그 editor Organization 제거 (Person만 허용되는 속성).
- 카테고리 CollectionPage의 실제 목록을 ItemList/ListItem으로 표현.
- 카테고리 영문 본문 존재 여부를 확인해 실제 언어 URL을 선택. 조회 실패를 빈 목록으로 표시하지 않음.
- JSON-LD `<` 이스케이프 및 실제 React 렌더링 회귀 검사.
- 사이트맵 DB 조회 제한 4초 → 10초.

기존 작업 파일을 리셋하거나 운영 릴리스 전체를 원본에 덮어쓰지 않았다. 카테고리는 변경 전 원본이 Git HEAD와 동일함을 확인하고 관련 운영 수정만 통합했다. 기타 파일은 해당 줄만 변경했다.

## 테스트·빌드 게이트

- `npm test`: 기존 Node 테스트 후 `npm run test:schema` 실행.
- `npm run test:schema`: 실제 JsonLd 컴포넌트를 렌더링해 script 종료 문자열과 Unicode 왕복을 검증.
- `npm run build`: npm의 `prebuild` 훅에서 `npm test`를 먼저 실행한다. 테스트 실패 시 빌드를 진행하지 않는다.
- `npm run typecheck`: TypeScript 별도 검사. Next 빌드에도 타입 검사가 포함된다.

직접 `next build`를 호출하거나 `--ignore-scripts` 옵션을 사용하면 npm prebuild를 우회하므로 배포에는 `npm run build`를 사용한다. 새 커밋/PR에는 기존 사용자 변경과 이번 변경을 검토하여 포함해야 한다. 작업 트리에만 있는 소스는 원격 CI에 자동 반영되지 않는다.

## 배포 설정 확인

원본 `ecosystem.config.cjs`는 `__dirname`을 cwd로 사용하며 Next를 127.0.0.1:3103에서 실행한다. 즉 이 설정을 새 릴리스 디렉터리에 복사하면 그 릴리스에서 실행된다. 토큰 파일은 별도로 관리되며 이번 작업에서 변경하지 않았다.

현재 운영은 `/Users/mainthive/project/ai-blog/.deploy/20261121-seo-p0/schema`이고 이전 정상 릴리스 `.../final`은 보존되어 있다. 이번 원본 통합 작업은 운영 서비스를 재시작하거나 교체하지 않는다. 기존 ADMIN 배포 문서의 11월 17일 경로는 당시 기록으로, 현재 운영 경로와 다르다.

다음 배포 순서:

1. 원본의 검토된 변경을 새 독립 릴리스에 복사한다. `.git`, `.next`, `.deploy`, 임시 검증 산출물은 복사하지 않는다. 환경변수·비밀정보는 기존 승인된 방식으로 별도 공급한다.
2. 릴리스에서 의존성을 준비하고 `npm run build`를 실행한다. 기존 개발 서버가 사용하는 원본 `.next`에 운영 빌드를 쓰지 않는다.
3. 빈 로컬 포트에서 새 릴리스를 실행하여 대표 글·카테고리·시리즈, sitemap, canonical/hreflang을 검증한다.
4. 검증된 릴리스의 ecosystem 설정에서 `--only thivelab-web`으로 웹 프로세스만 교체한다. 전체 apps를 재시작하지 않는다. 원본 설정으로 실수로 cwd를 되돌리지 않는다.
5. 운영 포트·공개 URL을 확인한 후 PM2 상태를 저장한다. 실패하면 보존한 이전 릴리스로 복원한다.

후속 P0 비교·통합을 완료했다. 번역 리다이렉트, 본문 기반 사이트맵/hreflang, URL 정규화, 시리즈 조회 오류 처리를 원본에 통합했다. 원본의 기존 색인 정책과 301 처리는 보존했다. 상세 검증과 다음 배포 명령은 `P0_SOURCE_INTEGRATION_2026-11-21.md`를 참고한다.
