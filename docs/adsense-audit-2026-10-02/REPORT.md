# THIVELAB AdSense·콘텐츠 점검 — 2026-10-02

이 문서는 확인된 사실과 편집 후보를 구분한다. AdSense 승인 여부는 Google 계정 심사 결과에 달려 있으며 이 점검으로 보장되지 않는다. 코드 변경은 **아직 배포하지 않았다**. DB 글 4건은 직접 수정했고 캐시 재검증을 호출했다.

## 기술·기능 검증

- 저장소: Next.js 16.2.7 문서의 robots, sitemap, not-found 규약 확인. 공개 글과 가이드는 PostgreSQL/Supabase에 있고, 글 생성 API는 기본 draft·발행 승인 필드를 사용한다. 과거 스크립트 중 직접 `published`를 쓰는 생성 스크립트가 있어 운영 호출 경로 확인 필요.
- 실서버: `https://www.thivelab.com/` 200, 임의 미존재 경로 404, `robots.txt` 200, `ads.txt` 200에 실제 `pub-2091277631590195`, `sitemap.xml` 200. 표본의 canonical은 대표 호스트로 출력. **`http://thivelab.com/`은 자기 자신으로 301이 반복되어 HTTPS에 도달하지 못함.** `https://thivelab.com/`은 대표 호스트로 301 후 200. Cloudflare/WAF의 Google AdSense 크롤러 실제 접근 로그는 미확인.
- 실서버 사이트맵 568개 `<loc>`를 HEAD로 전부 검사했고 568개 모두 200이었다. 각 항목의 본문·canonical·lastmod·hreflang 정확성은 전수 검증하지 않았다. 빈 카테고리의 사이트맵 포함을 막고 개인정보처리방침 lastmod를 실제 변경일로 갱신하는 코드 수정. **배포 필요.**
- `game.thivelab.com`과 `moa.thivelab.com` 첫 HTML은 200이고 AdSense 문자열은 발견되지 않음. 렌더링 후 요청, 내부 화면, 계정에서 코드 공유 여부는 별도 확인 필요.
- `npm run build` 성공, 1,488 정적 페이지 생성. 로컬 HTTP 표본에서 홈·수정 글·검색·개인정보 페이지 200, 없는 글·태그 404, 승인 플래그 미설정 시 AdSense 스크립트 없음. 로컬 `ads.txt`는 ID 환경변수가 없어 404이며 실서버는 200. 이는 가짜 ID를 쓰지 않는 의도된 구성.
- 브라우저 연결이 제공되지 않아 실제 모바일·데스크톱 화면, 메뉴·목차·검색·폼 성공 흐름·가로 스크롤은 이번 세션에서 시각적으로 검증하지 못했다. 성공 제출로 DB에 테스트 개인정보를 만들지 않았다. 배포 뒤 실제 기기 검증 필요.

## 계정·운영 확인과 심사 전 잔여 작업

1. **HTTP 리디렉션 루프를 먼저 수정한다.** Cloudflare와 원본 서버의 중복/자기 참조 규칙을 확인하고 `http://thivelab.com/` → `https://www.thivelab.com/`의 최종 200을 재검증한다.
2. AdSense 계정에서 소유권 확인 방식(ads.txt, Search Console 또는 코드), 자동 광고 상태, 사이트/정책 센터 상태, 실제 게시자 ID를 확인한다. 저장소의 ID 기본값은 제거했고 배포 환경변수에 유효한 `NEXT_PUBLIC_ADSENSE_ID`가 있어야 승인 후 코드가 동작한다. 승인 전 소유권 확인이 ads.txt인지 계정에서 확인해야 한다.
3. EEA·영국·스위스에 광고를 제공한다면 Google 요구에 맞는 인증 CMP·동의 설정을 계정에서 확인한다. 일반 배너를 구현했다고 보고하지 않는다. [Google 동의 요건](https://support.google.com/adsense/answer/13554116?hl=en).
4. 배포 후 모바일·데스크톱에서 메뉴, 검색·필터·페이지 이동, 시리즈 순서, 목차와 관련 글, 표·코드·이미지 넘침, 문의·구독·댓글·해지 성공/오류, 빈 결과, 404를 실제로 점검한다. 광고 네트워크 클릭이나 인위적 노출은 하지 않는다.
5. 댓글은 승인 상태만 노출되고 신고 메일 링크를 추가했지만, 전용 신고 큐와 관리자 숨김 UI는 없다. 운영자가 신고를 확인하고 DB 상태를 바꿀 절차를 마련한다. 이미지·인용·코드의 권리, 보안 글의 허가된 실습 맥락, 서브도메인 내부 화면, 실제 보관·삭제 설정도 사람이 확인한다.
6. 공개 글 전체의 출처·날짜·명령을 순차 검토하고 편집 기록을 실제 근거에 맞게 채운다. 대량 삭제·일괄 비공개는 시행하지 않았다. **코드 배포와 AdSense 심사 신청은 별도 지시가 필요하다.**
