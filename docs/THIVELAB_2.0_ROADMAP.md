# THIVELAB 2.0 로드맵·구현 계획

기준: 2026-10-09. 근거는 [현황 진단](./THIVELAB_2.0_AUDIT.md). 이 문서는 설계이며 운영 코드·DB·DNS·Cloudflare 라우트·배포를 변경하지 않는다. 기존 브랜드의 첫 진입은 THIVELAB, 콘텐츠는 NODELOG, 실습은 CIPHER, MOA는 기존 목적을 유지한다. TOOLS는 새 소비자용 진입점이다.

## 목표 구조

```text
www.thivelab.com  → 기존 NODELOG Next.js :3103 / 기존 URL·DB·SEO 유지
game.thivelab.com → 기존 CIPHER :3100
moa.thivelab.com  → 기존 MOA :5173
tools.thivelab.com → 신규 정적 TOOLS 앱 / 별도 저장소·빌드·로컬 포트
                         └─ 이미지·PDF·텍스트 파일은 브라우저에서 처리
미래(별도 결정)       → 인증·AI Cost Gateway·크레딧 원장·결제
```

처음에는 TOOLS 앱에서 NODELOG DB, 회원 계정, 결제, AI API를 호출하지 않는다. 브라우저 파일 처리 결과를 서버에 저장하지 않는다. 이 독립성으로 장애·용량·배포 범위를 구분한다. 도메인과 기존 URL은 그대로 두고 명시적인 상호 링크만 추가한다.

## 1. 무료 MVP: 6개 도구

모두 각 도구의 설명·지원 형식·크기 제한·오류 안내가 있는 고유 정적 URL을 갖는다. 처리 성능과 형식 지원은 실제 브라우저 시험 뒤 표시한다.

| 우선 | 도구·예상 경로 | 사용자 작업·범위 | 주의·검증 |
| --- | --- | --- | --- |
| P1 | 이미지 크기·용량 조절 `/image/resize` | 로컬 이미지를 지정 크기/품질로 다시 저장 | Canvas 지원 형식·투명도·EXIF/색상 프로파일 손실을 실제 파일로 검증. 원본 보존 안내 |
| P1 | 이미지 형식 변환 `/image/convert` | PNG/JPEG/WebP 지원 범위에서 변환 | 브라우저별 인코딩 지원 감지, 알파 채널·애니메이션·HEIC는 무리하게 지원 주장하지 않음 |
| P1 | PDF 합치기 `/pdf/merge` | 여러 로컬 PDF의 페이지 순서를 조정해 한 파일로 저장 | 암호 PDF/손상 파일/대형 문서 실패 처리, 페이지 수·메모리 제한. 파일을 네트워크로 전송하지 않음 |
| P1 | PDF 페이지 추출 `/pdf/extract` | 입력 PDF의 지정 페이지를 새 PDF로 저장 | 범위 파싱, 빈 범위, 중복/역순, 암호 PDF 오류 검증 |
| P1 | 텍스트 차이 비교 `/text/diff` | 두 텍스트의 줄·단어 차이 표시와 복사 | 긴 입력에서 메인 스레드 정지 방지, 데이터는 URL/분석 이벤트에 포함하지 않음 |
| P1 | JSON 검사·정렬 `/text/json` | JSON 문법 오류 위치, 정렬·압축·복사 | JSONC/JSON5 지원을 암시하지 않음, 매우 큰 입력 제한, 입력 원문 로그 금지 |

PDF 라이브러리와 브라우저 API는 MVP 프로토타입에서 파일별 메모리·속도를 측정해 확정한다. 정적 앱이라도 다운로드 파일명, MIME, 객체 URL 해제, 취소와 오류 상태를 검증한다. OWASP는 파일을 신뢰할 수 없는 입력으로 취급하고 파일 파서·공개 저장·악성 콘텐츠 위험을 구분한다. 여기서는 업로드 자체를 없애 위험 범위를 줄이되 브라우저 파서와 라이브러리도 검증한다: [OWASP File Upload Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html), [Web Frontend Security](https://cheatsheetseries.owasp.org/cheatsheets/Web_Frontend_Security_Cheat_Sheet.html).

## 3. 디렉터리와 환경 분리

제안 구조(아직 생성하지 않음):

```text
~/project/ai-blog/              # 기존 NODELOG 운영 저장소; 기존 경로 유지
~/project/thivelab-tools/       # 신규 독립 저장소
  app/                           # 도구별 HTML 진입점·설명 페이지
  src/shared/                    # UI, 파일 한도, 오류, 다운로드
  src/tools/                     # image/, pdf/, text/ 처리 모듈
  tests/                         # 단위·브라우저 파일 fixture·접근성
  docs/                          # 지원 형식, 개인정보, 배포·복구
  dist/                          # 정적 빌드 산출물
~/deploy/thivelab-tools/releases/<id>/  # 버전별 읽기 전용 산출물
~/deploy/thivelab-tools/current          # 활성 버전 포인터(검증 뒤 전환)
```

도구 앱에는 별도 정적 서버를 쓰고 localhost에만 bind한다. 호스트 포트는 현재 점유 상태를 확인한 뒤 예약한다(예: 3110, **미확정**). 개발은 별도 checkout·임시 포트, 스테이징은 운영과 다른 정적 빌드·접근 제한 hostname, 운영은 고정 버전 산출물로 분리한다. 현재 NODELOG DEV `:3104`는 모든 인터페이스에서 수신하고 같은 저장소를 쓰므로 TOOLS의 스테이징 기준으로 재사용하지 않는다. 스테이징 접근 제한이 검색봇에 노출되지 않도록 별도 호스트·`noindex`·인증을 함께 검토한다.

정적 멀티 페이지는 각 도구 설명과 메타가 초기 HTML에 들어가도록 한다. 앱 전체를 한 SPA fallback으로 반환해 없는 URL까지 200으로 만드는 구성을 피한다. 모든 도구 페이지에 지원 범위, 단계, 개인정보 처리, 관련 도구, 명확한 오류 메시지를 둔다. PDF용 라이브러리는 실제 시험 뒤 선택·버전 고정한다.

## 4. 메인·콘텐츠 연결 UX

- THIVELAB 공통 메뉴에는 `TOOLS` 외부 호스트 링크와 명확한 설명을 둔다. 신규 TOOLS 진입 영역은 NODELOG 글 목록을 밀어내거나 기존 서비스 카드를 숨기지 않게 배치한다. 모바일에서는 최소 터치 영역과 초점 순서를 확인한다.
- NODELOG 글에는 도구가 해당 문제를 실제로 해결할 때만 문맥형 링크를 둔다. 예: 이미지 최적화 글→크기 조절, PDF 워크플로 글→합치기. 링크는 작업 결과나 적용 환경을 과장하지 않는다. 일괄 삽입 대신 대상 URL 목록과 독자 목적을 검토한다.
- TOOLS에서는 관련 NODELOG 해설로 역링크를 제공한다. 기존 `/blog`, `/engineer`, `/series` slug·canonical·hreflang·RSS·redirect는 수정하지 않는다. 기존 디자인 언어와 브랜드 명칭을 참고하되 TOOLS 자체의 페이지 목적을 분명히 한다.

## 5. 파일 처리·보안·자원 한도

- 기본은 `<input type=file>` 또는 드롭 영역에서 사용자가 고른 파일만 처리한다. 파일 바이트·본문·이름을 API, 광고, 분석, URL 쿼리, 서버 로그에 보내지 않는다. 브라우저 자동 저장을 만들지 않으며 탭 종료 시 상태를 잃는다고 안내한다.
- 파일 MIME 선언과 실제 디코딩 결과를 함께 다루고, 지원하지 않는 형식·암호화 PDF·손상 파일에 명확한 오류를 준다. 다운로드는 Blob URL을 만들고 사용 후 해제한다. DOM 삽입은 텍스트 노드로 처리하고 HTML 미리보기를 실행하지 않는다.
- 초기 한도 **제안값**: 파일당 25MiB, 작업당 합계 100MiB, 최대 20개·PDF 200페이지, 텍스트 2MiB. 구현 전에 저사양 모바일·Safari/Chrome/Firefox 파일 시험으로 수치를 조정한다. 브라우저 메모리 부담을 줄이려 처리 중 중복 작업을 막고 취소/새 작업을 제공한다.
- 이 한도는 품질·보안 게이트이며 수익 조건이 아니다. 정적 자산에는 Cloudflare 요청 제한과 캐시를 적용할 수 있으나 구체값은 계정 플랜·트래픽 측정 뒤 결정한다. 서버 업로드·변환 API를 추가하는 단계에서는 별도 파일 검증, 격리, 저장 만료와 악용 방지 설계가 필요하다.

## 6. 광고·분석·미래 확장

- MVP 분석은 `tool_open`, `file_selected`(개수/형식 범주만), `conversion_success`, `conversion_error`(오류 코드만), `download_click`, `nodelog_referral` 정도로 설계한다. 파일 이름·텍스트·페이지 내용·해시·이메일은 이벤트 속성에 넣지 않는다. 실제 제공자의 동의·개인정보 고지는 기존 방침과 TOOLS 구현을 대조해 공개 전에 확정한다.
- 광고는 승인·정책·동의 요건을 별도 검토한 뒤 사용자가 작업 내용을 읽는 화면에만 배치 후보를 잡는다. 결과 다운로드·업로드·복사 버튼과 광고를 혼동시키지 않는다. 실패·빈 상태와 단순 완료 화면의 자동 광고 범위를 계정 설정까지 확인한다. TOOLS 도메인의 광고 적용 여부를 자동으로 기존 도메인에서 상속된다고 가정하지 않는다.
- AI Cost Gateway는 미래 별도 서버 서비스다. 사용자의 명시 요청→인증→쿼터·가격 확인→비용 한도→제공자 호출→사용량·결제 원장 기록 순서로 설계한다. API 키·원장·결제 웹훅을 정적 앱이나 NODELOG DB에 직접 넣지 않는다. 초기에는 URL이나 버튼으로 존재하지 않는 AI 기능을 약속하지 않는다.

## 7. 배포·롤백과 테스트 계획

### 승인 전 준비

1. 운영 `www` 주요 URL, 두 언어, 대표 글/가이드, 검색, 404, HTTP→HTTPS, robots/sitemap/RSS/ads.txt의 상태·canonical·hreflang·본문 해시를 기록한다. NODELOG DB 백업을 격리 DB에 복원해 확인한다.
2. TOOLS 정적 빌드를 독립 CI에서 만들고 HTML·JS·CSS·도구 fixture를 테스트한다. 산출물과 Git SHA를 고정한다. DEV·스테이징은 운영 `.next`나 포트를 사용하지 않는다.
3. 스테이징에서 6개 도구 정상·대형·손상·지원하지 않는 입력을 모바일/데스크톱 주요 브라우저로 테스트한다. 키보드·스크린리더 레이블, 터치, 초점, 실패 후 재시도를 확인한다. 개발 도구 네트워크 탭에서 파일 데이터 전송이 없는지 확인한다.
4. Cloudflare의 실제 현재 라우트·DNS·WAF·캐시를 계정에서 확인하고 `tools` 신규 호스트만 추가하는 변경안을 검토한다. 기존 `www`, `game`, `moa`, `db` 라우트를 손대지 않는다. 공개 URL 전환은 사용자 별도 승인 뒤 실행한다. [Cloudflare Tunnel 공개 앱 가이드](https://developers.cloudflare.com/tunnel/get-started/).

### 운영 전환·되돌리기(계획)

- 정적 서버를 localhost 전용 새 포트에서 시작하고 헬스·404를 확인한 뒤 신규 hostname을 연결한다. HTML은 짧은 캐시, 해시가 붙은 정적 자산은 긴 캐시를 후보로 하되 실제 Cloudflare 규칙을 검증한다. DNS 전환 전후에 외부 HTTPS 응답과 리소스 요청을 비교한다.
- 되돌리기는 신규 hostname의 이전 정상 정적 산출물로 포인터를 복귀시키고 캐시를 정리한다. 호스트 라우트 자체가 문제면 신규 `tools` route만 비활성화한다. NODELOG 코드 변경(메뉴/연결 영역)을 별도 배포했다면 그 커밋만 되돌려 재빌드한다. 데이터 마이그레이션이 없으므로 DB 롤백은 일반적으로 필요 없지만 사전 백업은 유지한다.
- 전환 직후와 다음 날에 `www`, `game`, `moa`, `tools` 상태·오류율·CPU·메모리·디스크·터널 연결을 비교한다. 롤백 트리거는 기존 서비스 오류 증가, 기존 URL/canonical 변동, TOOLS 실패율 증가, 디스크·메모리 압박 등으로 사전 수치화한다. 현재는 기준선이 없어 임의 임계값을 확정하지 않는다.

### 자동화 게이트

- TOOLS: 순수 변환 함수의 fixture 테스트, 이미지 픽셀 크기/형식, PDF 페이지 순서·수, diff·JSON 출력, 손상 입력, 브라우저 E2E, 접근성·모바일 시각 점검.
- 기존 서비스: `npm run typecheck`, `npm run lint`, `npm test`, 독립 checkout의 프로덕션 빌드. URL 표본의 상태·redirect chain·canonical·hreflang·robots·JSON-LD·sitemap 멤버십·내부 링크를 이전 스냅샷과 비교한다. 기존 검색 지표는 Search Console에서 전후 추이로 관찰하되 단기 변동을 인과로 단정하지 않는다.
- 성능·운영: 정적 도구 최초 로딩과 작업 중 최대 메모리, 저사양 모바일 처리 시간, Cloudflare/PM2/Caddy 오류 로그, 호스트 디스크 및 백업 실패 알림. 파일명·내용이 로그·분석에 나타나지 않는지 검사한다.
