# 검색 노출 급감 점검 — 2026-10-16 KST

## 관측

Search Console 도메인 속성의 검색 실적 API에서 `dataState=final`, `date` 차원으로 조회했다. 날짜 표기는 Google 검색 실적의 태평양 시간 기준이다. 최근 잠정일은 회복 판단에서 제외한다.

| 기간 | Google 검색 클릭 | 노출 | 비고 |
| --- | ---: | ---: | --- |
| 2026-09-30~10-06 | 93 | 5,520 | 비교 주간 |
| 2026-10-07~10-13 | 15 | 1,138 | 동일 요일 비교, 클릭 -84%, 노출 -79% |
| 2026-10-07~10-10 | 13 | 1,082 | 초반 4일 |
| 2026-10-11~10-13 | 2 | 56 | 3일 합계, 하루 노출 16·21·19 |

10월 14일 잠정 노출은 62, 15일은 2였다. `dataState=all`의 최신 날짜는 불완전할 수 있으므로 회복 근거로 사용하지 않는다. Google 공식 [Search Analytics API 설명](https://developers.google.com/webmaster-tools/v1/searchanalytics/query)에 따르면 `final`은 확정 데이터, `all`은 최신 잠정 데이터를 포함한다.

같은 비교 주간의 페이지별 합계는 속성 전체 합계와 집계 방식이 다르므로 위 표에는 날짜 차원의 속성 합계만 사용했다. 페이지별 감소는 한국어와 영어 모두에서 나타났다. 특히 영문 SSH·systemd·Linux archive 문서와 한국어 개인정보 위탁·ISMS-P 문서가 큰 폭으로 감소했다.

추가 조회에서 같은 요일 3일씩 비교한 **노출이 기록된 URL 수**는 10월 4~6일 457개에서 10월 11~13일 44개로 줄었다. 페이지 차원의 노출은 한국어 1,070→33, 영어 1,378→33이다. URL 수와 페이지별 노출은 검색 실적 API가 제공한 행의 비교이며 색인된 전체 URL 수를 뜻하지 않는다.

## 확인한 사실

- 2026-10-07에 Vercel에서 Cloudflare Tunnel 기반 자체 호스팅으로 전환했다. 이때 Vercel Analytics 코드를 제거하고 GA4 코드는 유지했다. Vercel Analytics의 방문자 수는 전환 전후 비교 자료로 쓸 수 없다.
- 10월 16일 공개 HTML에는 GA4 측정 ID가 있지만 Cloudflare Web Analytics의 `beacon.min.js`는 보이지 않았다. `Cache-Control: no-transform`도 없었다. Cloudflare Web Analytics 자동 주입 설정·대시보드 수집 상태는 확인할 계정 접근이 없으므로 현재 방문자 기준선은 **GA4 자료로 먼저 확인**해야 한다. Cloudflare의 [Web Analytics 안내](https://developers.cloudflare.com/web-analytics/faq/)에 따르면 자동 설정은 HTML에 비콘 스크립트를 삽입한다.
- Google의 [2026년 9월 스팸 업데이트](https://status.search.google.com/incidents/XhUDXP7A67iHCD2kmbVu)는 9월 24일 시작해 10월 8일 종료됐다. 하락 시점과 겹치지만 해당 업데이트가 이 사이트에 적용된 원인이라는 증거는 없다.
- 10월 16일 공개 점검에서 홈과 사이트맵은 200이었다. 노출 감소가 큰 URL 20개의 최종 페이지는 모두 200이었고 `noindex`가 없었다. 이 중 3개는 의도된 308 리디렉션을 거쳐 대표 URL로 도착했다.
- Search Console URL 검사 API에서 노출 감소 상위 15개를 추가 확인했다. 14개는 `Submitted and indexed`이고 크롤링·색인 허용이었다. 나머지 1개는 의도된 308 이동으로 `Page with redirect`였다. 일부 글은 10월 13~16일에 Googlebot의 성공적인 크롤링 기록이 있다. 이는 **색인은 유지되는데 검색 노출이 거의 사라진 상태**를 가리키며, 사이트 전체 색인 차단은 관측되지 않았다. 단, 15개 표본으로 전체 색인 상태를 보증할 수는 없다.
- PM2와 Tunnel 오류 로그에서 **10월 9일 10:28~16:21 UTC(한국 시간 19:28~10월 10일 01:21)** 사이 원본 서버 `127.0.0.1:3103` 연결 거부가 1,126건 확인됐다. 같은 구간에 웹 프로세스 재시작 기록이 있고 `Failed to proxy ... ECONNREFUSED`가 반복됐다. 이는 실제 접속 오류의 증거다. 전체 요청 대비 오류율과 Googlebot에 대한 영향은 로그만으로 알 수 없어 이후 며칠의 검색 급락과 인과관계를 확정하지 않는다.
- Tunnel은 기본 QUIC 전송에서 연결이 반복적으로 끊겼다. 10월 11~13일에도 하루 12~40회의 연결 종료·재등록이 기록됐다. 개별 연결 재시도 중에도 다른 연결이 요청을 처리할 수 있어 연결 종료 횟수를 전체 사이트 장애로 해석하지 않는다.
- Search Console의 [공식 데이터 이상 기록](https://support.google.com/webmasters/answer/6211453?hl=en)에는 현재 이 기간의 일반 검색 실적 누락이 게시돼 있지 않다. 미게시 지연 가능성을 완전히 배제할 수는 없다.
- 기존 콘텐츠 감사(`docs/adsense-audit-2026-10-02/REPORT.md`)에는 외부 출처 URL이 없는 블로그 글 464편, 검토 시각이 비어 있는 글 540편, 기계 번역된 영문 글의 품질 미검토가 기록돼 있다. 이는 품질 검토가 필요한 근거이며 Google 정책 위반이나 이번 감소의 원인 판정은 아니다.

## 현재 판단과 조치 순서

현재 데이터만으로는 **회복 중이라고 말할 수 없다.** 10월 9일의 원본 접속 장애는 확인됐고, 검색 순위 시스템 변화와 Search Console 집계 문제도 아직 구분해야 한다. 공개 HTTP와 URL 검사 표본에서 사이트 전체 `noindex`·robots·대표 URL 오류는 확인되지 않았다. 근거 없이 전역 SEO 설정이나 다수 글의 색인 상태를 바꾸지 않는다.

### 10월 16일 운영 변경

Tunnel의 반복적인 QUIC 연결 실패를 줄이기 위해 `ecosystem.config.cjs`의 `thivelab-tunnel` 실행 인자에 `--protocol http2`를 추가하고 PM2 프로세스를 재시작·저장했다. 변경 전에 Cloudflare 7844/TCP 연결을 확인했고, 변경 뒤 Tunnel 로그의 4개 연결이 모두 `protocol=http2`로 등록됐으며 공개 홈·robots.txt·sitemap.xml이 200으로 응답했다. [Cloudflare 공식 실행 인자 설명](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/configure-tunnels/run-parameters/)에 따른 전송 방식 변경이다. 이는 접속 안정화 조치이며, 검색 노출 회복은 이후 Search Console 실적에서 별도로 확인해야 한다.

변경 뒤 약 17시간 동안 PM2의 Tunnel 프로세스는 온라인이었다. HTTP/2 연결 하나가 재연결된 기록은 3회 있으나 4개 연결을 유지했다. `cloudflared` 자체 메트릭은 약 20,000개 요청 중 원본 프록시 오류 16개와 HTTP 500 응답 3개를 보여준다(각각 약 0.08%, 0.02%). 이 메트릭은 프로세스 재시작 뒤 누적치이며 Googlebot만의 오류율은 아니다. Search Console은 같은 시점에도 10월 13일까지만 확정 데이터를 제공하므로 변경의 검색 실적 효과는 아직 측정할 수 없다.

1. GA4 또는 Cloudflare Web Analytics에서 10월 6~15일 일별 **Google 자연검색 세션**과 전체 세션을 확인한다. GSC 클릭만 급감했다면 집계 문제를, 두 지표가 함께 급감했다면 실제 유입 감소를 우선 조사한다. Vercel Analytics는 전환 후 수집이 중단됐다.
2. Search Console의 **수동 조치**, **보안 문제**, **페이지 색인**, **크롤링 통계**에서 10월 7일 이후 신규 문제와 호스트 오류 비율을 확인한다. API의 검색 실적과 URL 검사만으로 이 보고서들을 대체할 수 없다.
3. Cloudflare의 10월 7~13일 `www.thivelab.com` HTTP 상태 코드, WAF·봇 차단, Tunnel 5xx 추이를 확인한다. 특히 Googlebot 요청이 차단·실패했는지 분리한다.
4. 실제 방문도 하락했고 기술 오류가 없다면, Search Console에서 감소가 큰 검색어·페이지를 우선으로 원문 정확성, 독자에게 고유한 도움, 번역 품질, 중복과 근거를 사람이 검토한다. [Google의 검색 감소 진단 안내](https://developers.google.com/search/docs/monitor-debug/debugging-search-traffic-drops)는 급격한 대량 수정 전에 기술 문제·검색 업데이트·계절성·수동 조치를 구분하도록 권한다.

이 절은 10월 16일 당시의 확인 계획이다. 이후 GA4와 Search Console 계정 화면의 확인 결과는 아래 10월 18일 절에 기록했다. Cloudflare 계정 원자료는 여전히 확인 대기 중이다.

## 10월 18일 재확인 및 진단 도구

- Search Console API의 최신 확정일은 10월 14일이었다. 기존 주간 보고 스크립트를 전송 없이 실행한 결과, 10월 8~14일 클릭 15·노출 1,142로 직전 7일의 클릭 66·노출 4,400보다 각각 77%·74% 낮았다. 10월 14일 하루의 노출은 64였다. 아직 회복 추세를 확인할 수 없다.
- 10월 18일 공개 접속 점검에서 홈, `robots.txt`, `sitemap.xml`은 모두 HTTP 200이었다. 현재 응답이 정상이라는 뜻이며 10월 초의 크롤러 오류를 소급해서 배제하지는 못한다.
- Cloudflare 공식 Codex 플러그인(`cloudflare@cloudflare`, 1.0.2)을 설치했다. Cloudflare API MCP와 Tunnel 및 웹 성능 진단 스킬이 포함된다. 새 MCP는 Codex 새 세션에서 로드되며, 계정 데이터 조회에는 Cloudflare OAuth 승인이 필요하다. OAuth 권한 범위는 연결 시 검토해야 한다.
- GA4와 Search Console 데이터를 함께 조회할 수 있는 Windsor.ai 연결을 제안했다. 제삼자 서비스이므로 계정 연결 여부는 소유자가 결정하며, 현재 직접 연결된 것으로 간주하지 않는다. Search Console 검색 실적은 기존 서비스 계정으로 계속 조회할 수 있다.
- 다음 진단의 우선순위는 Cloudflare의 10월 7~14일 상태 코드·Googlebot 차단 기록과 Search Console의 크롤링 통계·수동 조치 확인이다. 이 기록 없이 알고리즘 업데이트나 콘텐츠 품질을 단일 원인으로 단정하지 않는다.

## 10월 18일 계정 화면에서 추가 확인

- Search Console 도메인 속성의 **수동 조치**와 **보안 문제** 보고서는 모두 `감지된 문제 없음`이다.
- `robots.txt`의 심각한 오류 1건은 `http://thivelab.com/robots.txt`의 9월 21일 리디렉션 오류다. 주 호스트 `https://www.thivelab.com/robots.txt`는 10월 8일 성공적으로 가져왔고, 현재 `http://thivelab.com/robots.txt`도 1회 리디렉션 후 HTTP 200이다. 이 오래된 경고를 10월의 전체 검색 급락 원인으로 볼 근거는 없다.
- 크롤링 통계(10월 15일까지)에서 `www.thivelab.com` 호스트는 **과거에 문제가 있었으나 최근 크롤링 가용성은 수용 가능**으로 표시된다. 90일 누적 Googlebot 요청의 6%가 5xx이지만, 5xx 예시의 최신 시각은 9월 15일이고 그래프도 그 이후 0이다. 따라서 이 90일 누적 비율을 10월 7~14일의 오류율로 해석하지 않는다. 서버 자체 로그의 10월 9일 원본 접속 오류가 실제 Googlebot 5xx로 이어졌다는 증거는 현재 크롤링 통계에 없다.
- 페이지 색인 보고서(10월 12일까지)는 색인된 페이지 약 1,000개를 보여주며 그래프에서 10월 초 사이트 전체 색인 붕괴는 보이지 않는다. 별도 5xx 사유 83개 URL의 표본에 표시된 마지막 크롤링은 모두 9월 초·중순이다. 표본 중 한 URL은 현재 200, 다른 URL은 404이므로 전체 83개를 일괄 `수정 결과 확인` 처리하지 않았다.
- 사이트의 GA4 측정 ID `G-WL5W341ZFQ`와 일치하는 운영 속성에서 **`google / organic` 세션은 9월 30일~10월 6일 121건에서 10월 7~13일 27건으로 약 78% 감소**했다. Search Console 클릭 감소와 함께 실제 Google 자연검색 유입 감소를 뒷받침한다. 같은 기간 `Organic Search` 전체는 148→66건, Direct는 176→1,788건이다. 전체 방문자 증가처럼 보이는 수치에는 Direct 급증이 섞여 있으므로 이를 검색 회복으로 해석하지 않는다. Direct 급증의 출처는 Cloudflare 요청·봇 통계로 추가 검증해야 한다.
- GA4 세션 수와 Search Console 클릭 수는 집계 기준과 시간대가 다르므로 두 수치가 일치할 필요는 없다. 각각 동일한 날짜 범위의 직전 주와 비교했을 때 감소 방향이 같다는 점을 근거로 삼는다.
- Search Console의 새 확정 자료에서 10월 15일은 클릭 0·노출 39였다. 10월 11~15일 일별 노출은 차례로 16·21·19·64·39로 낮은 수준이 이어졌고 회복 추세는 확인되지 않는다.
- Search Console API에서 같은 두 주간의 검색어 행은 660→156개였다. 양쪽 주간에 모두 등장한 70개 검색어의 노출은 385→119, 노출 가중 평균 게재 순위는 16.5→22.8이었다. 페이지 행은 608→444개였고, 양쪽에 등장한 346개 페이지의 노출은 4,878→1,296, 노출 가중 평균 게재 순위는 10.0→11.4였다. 일부 검색어의 순위 악화는 확인되지만 많은 페이지는 순위가 비슷한 채 노출만 크게 줄었다. 평균 순위와 행 수는 노출 구성의 변화에도 영향을 받으므로 이 값만으로 원인을 단정할 수 없다.
- 10월 18일 현재 `thivelab-web`과 `thivelab-tunnel` PM2 프로세스는 온라인이고 공개 홈은 HTTP 200이다. Tunnel 로그에는 10월 18일 08:50 KST 원본 연결 거부 1건이 남아 있다. `thivelab-web` 프로세스 생성 시각도 같은 순간이므로 웹 프로세스 교체 중의 짧은 틈일 가능성이 높다. 해당 요청의 사용자·Googlebot 여부와 배포 사유는 알 수 없다. 운영 서비스는 현재 이 저장소가 아닌 `nodelog-releases/20261013-thivelab-zoom` 빌드에서 실행 중이므로 이 저장소의 미배포 변경을 현재 서비스 상태로 간주하지 않는다.

## 10월 18일 Cloudflare 계정 진단

Cloudflare 대시보드에서 **호스트를 `www.thivelab.com`으로 제한**해 확인했다. 시간대는 대시보드의 GMT+9 표시를 따른다. Cloudflare 전체 도메인에 다른 서브도메인의 525·530 오류가 많으므로, 도메인 전체 오류율을 블로그 오류율로 사용하지 않는다.

- 10월 7일 00:00~15일 23:59: `www` 요청 285,390건, 5xx 859건(0.30%). 세부 코드는 502 733건, 500 122건, 522 2건, 520 2건이다. 5xx 그래프의 큰 피크는 10월 9일에 집중돼 기존 원본 연결 거부 로그와 시간상 부합한다. Cloudflare 원본 탭은 같은 기간 원본 연결 실패 61건, 원본 5xx 855건, 원본 오류율 0.34%를 표시한다.
- 5xx 요청 859건 중 싱가포르가 727건이고, 상위 경로는 `/en/policy` 37건, `/en/series` 35건, `/en/subscribe` 33건 등이다. 상위 사용자 에이전트는 여러 버전의 Windows Chrome 문자열이다. 이 분포는 자동화된 요청 가능성을 높이지만, 개별 요청의 봇 여부는 이 집계만으로 확정하지 않는다. `Googlebot` 문자열 요청의 오류 건수는 아래 10월 19일 절에서 별도로 확인했다.
- 같은 기간 Cloudflare 보안 분석의 차단 요청은 **21건(전체의 0.01%)**이다. 관리형 규칙 14건, 브라우저 무결성 검사 7건이며, 5xx로 필터링한 요청 중 차단은 0건이다. 광범위한 WAF 차단이 이번 검색 급락의 주원인이라는 근거는 없다.
- 최근 24시간 `www` 요청 17,580건 중 5xx는 8건(0.05%)이었다. 도메인 전체의 5xx 5,280건(19.88%)은 다른 서브도메인의 525·530을 포함하므로 블로그의 현재 오류율이 아니다.
- 10월 7~15일 `www` 요청은 285,390건으로 앞선 비교 기간보다 58% 증가했고, 싱가포르에서 151,270건이 발생했다. 같은 기간 GA4의 Direct 세션 급증과 함께 비정상 트래픽 가능성을 조사할 근거지만, 요청 수와 GA4 세션은 서로 다른 지표다. 국가 전체 차단이나 전역 Bot Fight Mode는 정상 사용자·검색 크롤러에 영향을 줄 수 있어 이 자료만으로 적용하지 않는다.

### 10월 18일 운영 업데이트

- Cloudflare 공식 MCP를 `Zone Read`, `Analytics Read`, `Account Analytics Read`, `Cloudflare Tunnel Read`, `Zone WAF Read` 권한으로 연결했다. 새 MCP 도구는 이 실행 중인 Codex 세션에 바로 나타나지 않아, 위 수치는 승인된 대시보드에서 호스트·기간 필터를 적용해 확인했다.
- Homebrew의 공식 `cloudflared`를 2026.3.0에서 2026.10.1로 업그레이드하고 PM2의 `thivelab-tunnel`을 재시작했다. 새 버전 로그에서 HTTP/2 Tunnel 연결 4개가 모두 등록되고 `www` 및 루트 도메인의 원본 서비스 매핑이 수신된 것을 확인했다. 공개 홈·`robots.txt`·`sitemap.xml`은 모두 HTTP 200이었다. 이는 운영 안정화 조치이며 검색 노출 회복은 이후 확정 Search Console 데이터로 확인해야 한다.

### 10월 19일 Googlebot 문자열 요청과 최신 실적

- Cloudflare에서 `www.thivelab.com`과 사용자 에이전트에 `Googlebot`이 포함된 요청으로 10월 7~15일을 필터링하면 약 1,480건 중 5xx는 **502 한 건(0.07%)**이었다. 이 필터는 문자열만 확인하므로 요청자가 실제 Googlebot인지 인증하지 않는다. 다만 대규모 Googlebot 5xx가 있었다는 근거는 이 자료에 없다.
- 같은 필터에서 402 응답 26건이 보이며, Cloudflare 원본 탭에서도 원본 4xx 26건으로 표시돼 원본에서 반환된 응답이다. 홈 3건, 일부 글 URL, 정적 폰트 등 여러 경로에 분산됐다. Cloudflare 시간 그래프에서는 **26건 모두 10월 7일 이른 시간대에 집중**되고 이후에는 402가 나타나지 않는다. 자체 호스팅 전환 문서(`docs/SELF_HOST_CLOUDFLARE.md`)도 전환 전 Vercel이 402를 반환했다고 기록한다. 따라서 이전 원본의 응답일 가능성이 있지만 정확한 DNS 전환 시각 및 개별 요청의 원본을 대조하지 못해 확정하지 않는다. 현재 Googlebot 사용자 에이전트로 홈과 글 표본을 다시 요청하면 모두 200이다. 실제 Googlebot 영향도 확인되지 않았으며, 이 일회성 26건만으로 사이트 전체 검색 노출 급락을 설명할 수 없다.
- 10월 16일 Search Console 확정치는 클릭 0·노출 13이다. 10월 10~16일 7일 합계는 클릭 6·노출 525로 직전 7일 50·3,513보다 각각 88%·85% 낮다. 아직 회복했다고 볼 수 없다.

### 현재 결론과 다음 판단 기준

확인된 기술 장애는 10월 9일 원본 서버 접속 실패다. Tunnel 전송을 HTTP/2로 바꾸고 `cloudflared`를 갱신한 뒤 현재 공개 응답과 프로세스는 정상이다. Cloudflare의 `Googlebot` 사용자 에이전트 요청에서 5xx 1건, 보안 차단 전체 21건, 색인 유지 및 Search Console의 최근 크롤링 기록을 함께 보면 **지속적인 대규모 크롤러 차단·5xx가 노출 급감의 주원인이라는 근거는 약하다**. 이 수치에는 사용자 에이전트 위조 가능성이 있으며 Googlebot의 실제 수집 범위를 완전히 증명하지 않는다.

검색 노출과 GA4의 Google 자연검색 세션이 모두 크게 줄어 실질적인 검색 유입 감소는 확인됐다. 검색 시스템 변화, 콘텐츠 품질, 검색 수요 변화의 기여도는 아직 분리되지 않는다. 회복 여부는 동일 요일 기준 Search Console **확정** 클릭·노출과 GA4 `google / organic` 세션을 다시 비교해 판단한다. 전역 색인 설정이나 방화벽을 추가로 바꿀 근거는 현재 없다.
